Your readers get a documentation site: navigation on the left, the article in the middle, search at
the top. It is generated by Document360 from your repository's content, and it is not itself in the
repository.

## What comes from where

[d360]: # 'table border="all" striped="true"'

| Part of the site | Comes from |
| :--- | :--- |
| Article content | The Markdown files |
| Navigation and ordering | `d360.json` |
| Titles, icons, SEO metadata | Each article's front matter |
| Tags shown to readers | `.document360/tags.json` plus each article's `tags` |
| Variables, substituted in the text | `.document360/variables.json` |
| Branding, theme, domain | Project configuration, not the repository |
| Access rules, if any | Project configuration, not the repository |

[d360]: # "/table"

> [!IMPORTANT]
> **Configuration is not content, and does not travel with a branch**
>
> Your logo, your domain and who may read the site are project settings. They are not in the
> repository, so they are not part of a pull request and not restored by reverting a commit. Treat
> them as a separate set of decisions with a separate record.

## What readers never see

| Never reaches the site |
| :--- |
| `internalDescription` in front matter |
| Labels |
| Private note blocks |
| Articles marked `hidden` |
| Articles with `search.exclude`, in search results |
| Anything on an unpublished branch |

> [!WARNING]
> **"Not shown to readers" is not the same as "secret"**
>
> Every item above is in the repository, so anybody who can read the repository can read it. That is
> usually a wider group than you think, and it will eventually include a contractor. Keep genuine
> secrets out of documentation entirely.

## Multiple languages

Where your project has several languages, readers get the one their browser asks for, falling back to
the default where an article has no translation. A partially translated knowledge base stays
navigable rather than showing gaps.

> [!NOTE]
> **A fallback is better than a gap, and worse than a translation**
>
> Readers who see an English page inside an otherwise German site know what has happened. Readers who
> hit a missing page do not. The fallback buys you time; it does not remove the need.

## Previewing before readers see it

You can look at a change as a reader will see it before anybody else does.

- A **draft on the tracked branch** previews with the ordinary knowledge base site preview.
- A **working branch** previews as readers would see it, including drafts you have not yet saved to
  the branch. Images that exist only on the branch show too.
- A **share link** sends one article, or one category, of a branch to a reviewer outside the project.
  It shows that item alone, with no navigation around it.

> [!IMPORTANT]
> **A share link dies with its branch**
>
> When the branch is merged, closed, deleted or ended, the link stops working — it never quietly
> falls back to the live page. Tell outside reviewers that, or they will think your documentation
> broke.

Preview is for signed-in users and follows the existing preview access rules. Content that exists
only on the branch inherits the access of its nearest parent category, and is not shown if none
applies.

> [!CAUTION]
> **The editor's rendering is a preview of the content, not of the site**
>
> The editor shows the blocks correctly. It does not show your theme, your navigation around the
> page, or how the article reads on a phone. For anything layout-sensitive, look at the published
> site rather than at the editor.

## Accessibility of what you write

Three things that are yours rather than the platform's, and that no configuration fixes:

[d360]: # 'multi-level-list styles="decimal,lower-alpha"'

1. **Alt text on every image.** A figure whose caption says "the settings screen" and whose alt text
   is empty is invisible to a screen reader.
2. **Headings in order**, without skipping levels. Headings are how a screen-reader user navigates a
   page.
3. **Link text that makes sense alone.** "Front matter" rather than "click here", because links are
   often read as a list.

[d360]: # "/multi-level-list"

[d360]: # 'callout kind="success"'

> **These are also the three things that help search**
>
> Alt text, ordered headings and descriptive links improve how a page is indexed and how an assistant
> answers from it. Accessibility and findability turn out to want the same things.

[d360]: # "/callout"
